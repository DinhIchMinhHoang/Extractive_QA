# Archive layout for Hugging Face

Nothing under `outputs/` or `data/` is ever deleted or moved: notebook-generated models are scientific evidence.
The upload is done by the maintainer: `hf auth login` once, then the manual commands below.

## Repos (`<user>` = `--user NAME` or `$HF_USER`)
| Repo | Type | Content |
|---|---|---|
| `<user>/viquad2-extractive-qa-archive` | dataset | `outputs/**` + `data/processed/**` + `data/MANIFEST.json`; excludes `outputs/release_dl` (duplicate download parts of release), `outputs/release_tmp`, `outputs/smoke_x`, `outputs/smoke_phobert_x`, `outputs/release/**` (goes to model repos; the dataset card points to them); `outputs/xlmr_base_out.tar`, `outputs/xlmr_large_out.tar`, `outputs/phobert_base_lr2e5_out.tar` (not part of the archive: same content as the extracted `outputs/xlmr_base/`, `outputs/xlmr_large/`, `outputs/phobert_base/`, which are included); `data/hf_cache`, `data/vncorenlp` (third-party) never included |
| `<user>/viquad2-xlmr-base` | model | `outputs/release/xlmr_base/**` (s42-s44) + `best_models.json` + card |
| `<user>/viquad2-phobert` | model | `outputs/release/phobert/**` (s42-s45; s44/s45 diverged, labelled in the card, excluded from ensemble) + `best_models.json` + card |
| `<user>/viquad2-xlmr-large` | model | `outputs/release/xlmr_large/**` (s42-s44) + `best_models.json` + card |

`best_models.json` is uploaded whole (it covers all 3 families; tiny), not as a per-model subset.
Cards live in `docs/hf_cards/` and are uploaded as `README.md`.

## Commands
Packaging (fp16 conversion, tar, 256 MB split, manifests) and the upload were done with temporary scripts (đã xoá khỏi repo ngày 2026-11-14, chưa từng commit, so they cannot be recovered from git history). The artifacts and both `MANIFEST.json` files remain.

Manual upload (chưa thử lại sau khi xoá script): `hf auth login` once, then per repo
```
hf upload <user>/<repo> <local_dir> --repo-type model|dataset --include "<glob>" --exclude "<glob>"
```
as documented by `hf upload -h`. `hf upload-large-folder` is NOT available in `huggingface_hub` 2.4.0. Add `--private` for a private first try.

Manifest format (`outputs/MANIFEST.json`, `data/MANIFEST.json`): JSON with `created`, `git_commit`, `excludes`, `file_count`, `total_size`, and `files`: a map from relative path (relative to the manifest's folder, `/` separators) to `{"size": <bytes>, "sha256": "<hex>"}`. To verify by hand, compare each file's size and sha256 with any tool, e.g. `sha256sum <file>` (Linux/Git Bash) or `Get-FileHash <file> -Algorithm SHA256` (PowerShell).
`outputs/MANIFEST.json` also lists `outputs/release/**` (kept for local verification); the dataset repo itself does not contain it.
`outputs/MANIFEST.json` is the local manifest and still lists the 3 excluded tars (`xlmr_base_out.tar`, `xlmr_large_out.tar`, `phobert_base_lr2e5_out.tar`); it was not regenerated. All tars stay on disk locally. The extracted folders hold the same `model.safetensors`, tokenizer and summary files. `outputs/phobert_base_out.tar` (diverged lr 3e-5 run, no extracted copy) stays in the archive. Verifying a downloaded copy against this manifest reports those 3 tars as missing; expected.
After any change under `outputs/` or `data/processed`, the manifests are stale; there is no script to regenerate them now.
